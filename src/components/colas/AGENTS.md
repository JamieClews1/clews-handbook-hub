# Colas Rail

- Colas Rail reporting (/colas-rail) is a separate module: figures are computed by colas-report.ts from completed Skiptrak jobs (linked Midweigh only fills missing weights), colas_* manual/Sage/consignment tables and opening balances; approvals freeze a snapshot, and missing data is flagged, never treated as zero. Colas customer access stays off until a Clews administrator authorises it.
- The spreadsheet-style "breakdown of waste arisings" (screen, PDF, Excel) comes from buildArisings: recycled / energy recovery / landfill tonnes are each stream's tonnes split by the per-stream treatment saved in colas_report_settings.stream_treatments (defaults in DEFAULT_TREATMENTS), because the source data records no fate per load; approval snapshots store the table so later treatment edits never change an approved month.
- Consignment notes that staff cannot read are recorded as colas_consignments.read_issue (unreadable / page_missing) and stay an outstanding issue on the monthly report, even when the source is approved, until a number is saved (saving a number clears the flag), so unreadable paperwork is never silently accepted.
- QuickConsign numbers are read automatically by the colas-consignment-reader function (managed HTTP schedule at 16:00 and 17:00 UTC; only the run landing on 17:00 London proceeds), using the scanned page images of each hazardous Colas job's newest wtn_documents scan. Each job + scan is read once (colas_consignment_scan_attempts), only a certain COLASR/nnnnn not already on another job is saved (a faint R read as COLAS/ is normalised, since the prefix is fixed, but the digits must be exact), saved numbers and staff-chosen reading flags are never overwritten, and staff edits clear auto_read_at; credit/access errors pause it until resumed in Sources & settings, so the reader can never silently change paperwork evidence.
- Jobs the reader couldn't read are listed in Sources & settings (ColasManualConsignments) for staff to type the number and their own note (colas_consignments.notes); it reuses the Hazardous tab rules (a number clears read_issue and auto_read_at, a note alone keeps the flag, a number already on another job is refused), so manual entry can never hide an unresolved note.
- Agreed assumed weights live as constants in colas-report.ts and apply only when no weight exists anywhere (Skiptrak, linked Midweigh or the manual entry): wheelie-bin Skiptrak lifts and B&M entries, and Fortress entries; agreed regular weekly collections (WEEKLY_COLLECTIONS from WEEKLY_COLLECTIONS_FROM) are added per Monday up to today unless staff entered that provider in the same week; such lines are marked weightSource "assumed" (weekly ones also weekly) and labelled on screen and in exports, so an estimate is never mistaken for a weighed figure or counted twice while every other missing weight stays flagged.
- The Sources & settings audit log is never edited or deleted: its Correct button opens the live record instead (consignment numbers via ColasConsignmentCorrection, which can move a number typed on the wrong job using planConsignmentMove; collection entries via the shared EntryDialog), so every correction becomes a new logged change and the original entry stays as evidence.
