# Route One components

- Route One booking search opens the read-only SiteContainersDialog, which reuses currentSiteContainers (the Live Jobs/Site History replay, clamped per Skiptrak site name like Live Jobs and listed per bin position with its last real movement) and only prefills the form; Book exchange goes through the existing previous-job applyPrevious path so imported pricing and exchange dates stay on one rule set.
- Previous artic (trailer) jobs are grouped by previousArticJobs in SiteContainersDialog and the previous-jobs list offers Duplicate (same job type, falling back to exchange when that type is switched off in Setup) or Exchange; both only prefill via applyPrevious, never save.
- SiteContainersDialog matches future Skiptrak/Route One bookings to each bin position (binFutureBookings: site + container + EWC) and detects the repeat interval; Book next exchange passes the last booking so applyPrevious dates the new exchange after it by that interval instead of the booking-window day.
- Scheduled jobs live in route_one_job_schedules; only generate_route_one_scheduled_jobs (invoker, staff-gated, daily pg_cron plus on save) inserts their unassigned route_one_jobs, unique per schedule+date, skipping dates within a few days of a matching Route One or Skiptrak booking and advancing booked_until so removed occurrences are never recreated.
- SiteContainersDialog presents bins and trailer streams as a read-only timeline (container-timeline builds dots/flags; ContainerTimeline renders): Skiptrak has no parent-job link, so a chain is the bin position's jobs in date order, and Open job / Move date only reopen the existing Route One editor; nothing on the timeline books, moves or saves.
- Live Jobs Site History reuses ContainerTimeline (List / Timeline switch, weeks/months zoom) over siteBinHistories for Skip sites only; it is view-only and a dot opens the existing job view, so booking actions never appear there.
