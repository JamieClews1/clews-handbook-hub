# src

Open tabs move onto a newer build automatically via the build-watchdog module-script signature; the dev server stamps the page with the newest source change time so an already-open preview tab reloads onto edited code, and dev tooling scripts are excluded from the signature.
- External inventory valuations use the shared server-side inventory-valuation helper, combining verified profiles with configured assumptions and explicitly reporting missing rates and reconciliation differences; share visibility gates remain authoritative.
- The installed Load Reports app is locked per window by launch address to Load Reports, Container Loads and sign-in; it is a device UI lock, not a permission, so browser tabs keep the full portal.
- Orders portal (/orders, Inbox → Orders portal): customers hold a secret per-conversation link and reach order_portal_* data and the private order-portal bucket only via the orders-portal function; staff use is_staff RLS, so it works without Outlook and never exposes other conversations.
- Orders portal attachments open in the shared in-app OrderFileViewer from fetched data (PDF pages drawn as images; blob links for download), never by navigating to storage addresses, because browser blockers refuse those pages.
- Inbox and Orders portal tab badges count what is in each inbox (unfiled email threads, orders not done) and put unread numbers in the tooltip, because synced email leaves thousands of threads unread so an unread-only badge would be permanently maxed out.
- Waste names/EWCs follow the agreed standard in waste-streams (data in waste-stream-standard.json): screens resolve recorded wording to the standard name at display time and stored job wording is never bulk-rewritten, because rebate filters and past reports match on it; portal EWC corrections set waste_corrected_at so Data Uploads keep them. New bookings, weighbridge price lines and Duty of Care products are chosen from the standard list (WasteStreamPicker) and wording carried into a new booking goes through standardBookingWaste, so non-standard names cannot re-enter. Screens show each stream's agreed reference code with WasteRefChip/WasteRefFor so staff can cross-check codes between systems. Rate-card lines priced by grade or covering several streams resolve to no stream and leave the waste for staff to choose. Haulage Only is the haulage_only Route One job type (no waste/EWC), not a waste choice; new configured job-type keys need a matching route_one_job_type database value or bookings of that type cannot save.
- Admin → Apps is the single home for installable app cards; the Office App card/guide read OFFICE_APP_TILES so listed features never drift from the launcher.
- Installable apps share the W1 home-screen icons (w1-icon-192/512, apple-touch-icon); app pages offer AddToHomeScreenButton, which uses one-tap install when offered and otherwise shows browser-specific steps, sending in-app viewers and framed pages (e.g. the editor preview) to open the app on its own because they cannot install; app cards carry a QR code so phones open the link in their normal browser.
- Office App Skip Tracker and Contaminations reuse the Driver App components with reporter type "office" (signed-in staff); driver-actions contamination_config also accepts a staff session, so office reports land in the same skip tracker and contamination records as drivers.
- Office App remembered sessions are kept current from the auth listener (session keys rotate on refresh), sign-in calls time out with a retry message, and a full portal password sign-in clears the Office App lock, so a device never sticks on a sign-in screen.
- Digital Waste Tracking shows the agreed waste name and reference code for display only; the DEFRA submission keeps sending the recorded waste wording and EWC, so receipts match the ticket paperwork and already-submitted loads stay consistent.
- Weighbridge minimum charges are derived in the database (triggers on weighbridge_waste_types/rate_group_prices): the chargeable weight is the waste type's own min_weight_kg when set, otherwise weighbridge_pricing_settings.min_charge_weight_kg (350 default), so every reader of stored min_charge (WeighOne, Banksman WTN) stays consistent; a waste-type trigger must use NEW.min_weight_kg because the table still holds the old row during BEFORE UPDATE, and exempt types (min_weight_exempt) keep a manually entered £ minimum.
- WeighOne Waste In payments are captured on the main ticket form and the ticket view through shared PaymentFields/weighone-payment helpers; the form's PDF/Print save first and print the saved row, so a downloaded ticket always matches the on-screen prices and payment.
- Live Jobs Site History groups every retained Skiptrak job into bin positions (site name + container + EWC) via siteBinHistories, taking on-site counts only from currentSiteContainers so it always agrees with Live Jobs; linked Midweigh tickets are read-only evidence and saved Customer Setup site links merge aliases into one search result.
- Container names follow the agreed standard in container-standard (data in container-standard.json), resolved from recorded wording at display time like waste streams; stored container wording is never bulk-rewritten because rebate filters, standing bins and over-rental marks match on it. Booking choices stay in container-taxonomy: bespoke sizes are offered without a price-list size, and history-only types are never booking choices.
- The portal type scale lives in CSS variables (--text-xs/sm/base/lg) mapped through Tailwind's fontSize, with an @media print reset to the compact scale, so screen legibility can change without moving printed paperwork; vehicle registrations use the shared .reg-plate class and on-screen weights use weight-format (3 dp tonnes).
- Site History search reads site_history_bank (one row per source/customer/site, kept current by a data_hub_jobs trigger and rebuilt nightly by pg_cron) through search_site_history_ranked, never scanning data_hub_jobs per search; opening a site still reads its full job history directly. RLS checks on hot tables wrap auth.uid() and role helpers in SELECT so they run once per query, not per row.
- Customer Setup's Find site by postcode reads the same site search bank (search_site_history_ranked, Skip and weighbridge) and only prefills empty site-form boxes and free Data Hub site slots, so it never overwrites typed details or saves before staff press Save.
- RAMS and Toolbox Talks are managed on their own pages: admins get a Manage tab (view=manage, optional edit=<id> or new=1 via hs-manage-view) that hosts the shared builders, and /admin/rams, /admin/toolbox-talks redirect there, so there is one editing home and the address can open a specific document; non-admins always get the documents list.
- The Toolbox Talks list sorts and filters through toolbox-talk-list (reference number order; a talk applies by user type or named assignment); admins also see talks not assigned to them, labelled, so newly published talks are always visible to whoever manages them.
- Customer portal cost columns split each imported job through portal-job-charges: Waste = Cost − Haulage Cost − Added Cost, read from the uploaded row, and shown only when the row carries Added Cost so older uploads never count extras as waste; Data Uploads already keep every spreadsheet column, so new upload columns need no upload change.
- auth-lock-guard is imported first in main.tsx: it time-limits session refresh calls and frees the sign-in library's browser lock when it stops moving, because a paused second window (browser tab or installed app on the same tablet) holding that lock otherwise blocks every page load and data request with no time limit.
- WeighOne Pricing groups waste types by family in weighbridge-price-groups (display only, General Waste first, unknown names under Other), so reordering the price list never changes stored display_order or prices.
